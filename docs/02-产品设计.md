# 02 · 产品设计 【提案】

## 核心流程

```
上传合同（PDF/DOCX/扫描件）
  → 解析为条款树（章-条-款-项）
  → 三层审查并行：
     ① 条款抽取：付款/交付/违约/知识产权/保密/争议解决/期限 …（结构化卡片区）
     ② 风险扫描：规则库 + LLM 双通道，标红分级
     ③ 模板差异：与用户自家模板逐条对比（团队版）
  → 报告页：原文与结论左右分栏，每条结论点击跳转原文位置
```

## 报告结构（产品的主交付物）

1. **总览卡**：合同类型识别、我方/对方角色、整体风险分级（绿/黄/红）、
   "必须人工确认"清单 Top3——10 秒版本；
2. **条款卡片区**：每类条款一张卡（金额/期限/触发条件/后果），缺失条款显式列出
   "未见 X 条款"（缺失检测与错误检测同等重要——采购最怕"没写违约金"而不是"违约金写错"）；
3. **风险清单**：每条 = 风险描述 + 等级（高/中/低）+ 原文引用 + 建议动作
   （"建议补充逾期利息条款，参考模板第 X 条"）+ "去问律师"标记位；
4. **差异对比**（团队版）：左我方模板右来件合同，逐条高亮偏离。

## 风险分级体系（产品专业度的核心，也是内容营销素材）

规则库双通道设计：

- **确定性规则**（规则引擎，不用 LLM）：金额大小写不一致、付款条件缺逾期条款、
  违约金上限超过法定上限、管辖地缺失、阴阳条款（前后矛盾）——可精确测试、零幻觉；
- **LLM 语义审查**（带引用约束）：责任不对等、单方解除权、模糊表述
  （"及时""适当"类不可量化词）、与行业惯例偏离——每条结论必须附原文引用，
  引用与原文做字面校验，校验不过该条直接丢弃（宁缺勿错，防幻觉红线）。

规则库 v1 目标 80 条（采购合同 40 + 贸易 20 + 通用 20），每周从审查记录里补——
规则库本身是持续资产，形态对标工具链项目的"检测规则 + 例外清单"打法。

## 信任设计（法律工具的生死线）

- 每条结论可回溯原文（点击滚动定位 + 高亮）；
- "不确定"是合法输出：LLM 低置信条款归入"待人工"而非硬猜；
- 全局免责声明 + "建议咨询律师"引导（与 01 的定位红线一致）；
- 隐私承诺：默认即删（审后 24h 清除原件），团队版可开"仅存报告不存原文"。

## 模板库冷启动

- 内置 6 类基础模板（采购/销售/服务/租赁/劳动/保密），来源：公开示范文本
  （政府/协会发布版）+ 律师朋友审核；
- 用户上传自家模板 → 抽成条款树 → 后续差异对比基于它。

## 明确不做（M0）

- 不做合同起草（审查做深再说）；
- 不做电子签约/存证（法大大的地盘）；
- 不做英文之外的多语种（中英双语是 P0' 需要，够用即止）。
